# 宠物管理系统设计文档

## 3.1 系统需求分析

### 3.1.1 系统边界与角色定义

本系统面向三类用户：前台普通游客、前台注册会员和后端管理员。

**系统上下文图：**

```
┌──────────────┐
│  普通游客     │
└──────┬───────┘
       │
       ▼
┌──────────────────────────────┐
│      宠物管理系统               │
├──────────────────────────────┤
│  - 宠物信息浏览                │
│  - 宠物搜索                    │
│  - 用户注册登录                │
│  - 领养申请                    │
│  - 预约管理                    │
└──────┬───────────────────────┘
       │
       ▼
┌──────────────┐
│  注册会员     │
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  系统管理员   │
└──────────────┘
```

### 3.1.2 功能性需求

#### 模块一：宠物管理模块

**用例UC-01：弃养宠物信息录入**
- 参与者：系统管理员
- 前置条件：管理员已登录系统
- 基本流程：
  1. 管理员进入宠物管理页面
  2. 点击"添加宠物"按钮
  3. 填写宠物基本信息（名称、类型、品种、年龄等）
  4. 填写健康状况描述
  5. 上传宠物照片
  6. 提交信息
  7. 系统验证信息完整性
  8. 保存宠物信息到数据库
- 后置条件：宠物信息成功录入系统

**用例UC-02：弃养宠物信息修改**
- 参与者：系统管理员
- 前置条件：宠物信息已存在
- 基本流程：
  1. 管理员进入宠物管理页面
  2. 选择要修改的宠物
  3. 修改需要更新的信息
  4. 提交修改
  5. 系统验证信息有效性
  6. 更新数据库中的宠物信息
- 后置条件：宠物信息更新成功

**用例UC-03：弃养宠物信息删除**
- 参与者：系统管理员
- 前置条件：宠物信息已存在
- 基本流程：
  1. 管理员进入宠物管理页面
  2. 选择要删除的宠物
  3. 点击删除按钮
  4. 系统弹出确认对话框
  5. 管理员确认删除操作
  6. 系统从数据库中删除该宠物信息
- 后置条件：宠物信息被删除

**用例UC-04：弃养宠物信息查询**
- 参与者：系统管理员、普通游客、注册会员
- 前置条件：无
- 基本流程：
  1. 用户进入宠物查询页面
  2. 输入查询条件（名称、类型、品种等）
  3. 点击查询按钮
  4. 系统根据条件检索数据库
  5. 显示查询结果列表
- 后置条件：显示符合条件的宠物信息

#### 模块二：领养申请管理模块

**用例UC-05：领养申请列表查看**
- 参与者：系统管理员
- 前置条件：管理员已登录系统
- 基本流程：
  1. 管理员进入领养申请管理页面
  2. 系统显示所有领养申请列表
  3. 列表展示申请核心信息（申请人、宠物、状态、时间等）
  4. 管理员可按条件筛选申请
- 后置条件：管理员查看所有申请记录

**用例UC-06：领养申请审核**
- 参与者：系统管理员
- 前置条件：存在待审核的领养申请
- 基本流程：
  1. 管理员选择待审核的申请
  2. 查看申请人信息和宠物信息
  3. 根据审核标准做出决定
  4. 选择"通过"或"拒绝"
  5. 填写审核意见
  6. 提交审核结果
  7. 系统更新申请状态
  8. 系统通知申请人审核结果
- 后置条件：申请状态更新，申请人收到通知

**用例UC-07：在线提交领养申请**
- 参与者：注册会员
- 前置条件：用户已登录系统
- 基本流程：
  1. 用户浏览待领养宠物列表
  2. 选择感兴趣的宠物
  3. 查看宠物详情
  4. 点击"申请领养"按钮
  5. 填写领养申请表单
  6. 提交申请
  7. 系统验证申请信息
  8. 保存申请记录
  9. 系统提示申请提交成功
- 后置条件：领养申请记录创建成功

**用例UC-08：申请状态查询**
- 参与者：注册会员
- 前置条件：用户已提交领养申请
- 基本流程：
  1. 用户进入个人中心
  2. 点击"我的领养申请"
  3. 系统显示用户的所有申请记录
  4. 用户查看申请状态和审核意见
- 后置条件：用户了解申请进度

#### 模块三：预约管理模块

**用例UC-09：预约信息查看**
- 参与者：系统管理员、注册会员
- 前置条件：已登录系统
- 基本流程：
  1. 用户进入预约管理页面
  2. 系统显示预约记录列表
  3. 列表展示预约时间、预约人、宠物等信息
  4. 用户可查看预约详情
- 后置条件：用户查看预约信息

**用例UC-10：预约确认**
- 参与者：系统管理员
- 前置条件：存在待确认的预约
- 基本流程：
  1. 管理员查看预约列表
  2. 选择待确认的预约
  3. 核实预约信息
  4. 点击确认按钮
  5. 系统更新预约状态为"已确认"
  6. 系统通知用户预约已确认
- 后置条件：预约状态更新，用户收到通知

**用例UC-11：在线预约探视**
- 参与者：注册会员
- 前置条件：用户已登录系统
- 基本流程：
  1. 用户浏览宠物列表
  2. 选择要探视的宠物
  3. 点击"预约探视"按钮
  4. 选择探视时间
  5. 填写预约信息
  6. 提交预约申请
  7. 系统保存预约记录
  8. 系统提示预约提交成功
- 后置条件：预约记录创建成功

**用例UC-12：预约取消**
- 参与者：系统管理员、注册会员
- 前置条件：预约记录存在
- 基本流程：
  1. 用户进入预约管理页面
  2. 选择要取消的预约
  3. 点击取消按钮
  4. 系统弹出确认对话框
  5. 用户确认取消操作
  6. 系统更新预约状态为"已取消"
  7. 系统通知相关人员
- 后置条件：预约状态更新

### 3.1.3 非功能性需求

#### 性能要求
- 系统支持至少100个并发用户同时访问
- 页面响应时间小于3秒
- 数据库查询响应时间小于1秒
- 图片加载时间小于2秒

#### 安全性
- 用户密码采用BCrypt加密存储
- 敏感数据传输使用HTTPS加密
- 实现SQL注入防护
- 实现XSS攻击防护
- 实现CSRF攻击防护
- 用户登录失败超过5次锁定账户30分钟

#### 可靠性
- 系统支持7×24小时运行
- 重要数据每日自动备份
- 系统故障恢复时间小于1小时
- 数据丢失率为0

#### 易用性
- 界面简洁美观，符合用户操作习惯
- 提供清晰的操作提示和错误信息
- 支持主流浏览器访问
- 移动端适配良好

#### 可维护性
- 代码结构清晰，注释完整
- 模块化设计，便于扩展
- 提供完善的日志记录
- 支持在线升级

## 3.2 系统概要设计

### 3.2.1 系统总体架构设计

本系统采用B/S架构，前后端分离设计。前端使用HTML+Bootstrap+JavaScript实现，后端使用Spring Boot框架开发，数据库采用MySQL。

**系统架构图：**

```
┌─────────────────────────────────────────────────┐
│                  表现层                          │
│  ┌──────────────┐  ┌──────────────┐           │
│  │  PC浏览器     │  │  移动浏览器   │           │
│  └──────┬───────┘  └──────┬───────┘           │
└─────────┼──────────────────┼──────────────────┘
          │                  │
          ▼                  ▼
┌─────────────────────────────────────────────────┐
│                  前端层                          │
│  ┌──────────────┐  ┌──────────────┐           │
│  │  HTML页面     │  │  Bootstrap   │           │
│  │  JavaScript   │  │  样式框架     │           │
│  └──────┬───────┘  └──────────────┘           │
└─────────┼──────────────────────────────────────┘
          │
          ▼
┌─────────────────────────────────────────────────┐
│              表示层（Controller）                │
│  - 处理HTTP请求、响应                            │
│  - 参数校验                                      │
│  - 统一异常处理                                  │
└──────────────────┬──────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────┐
│            业务逻辑层（Service）                 │
│  - 实现核心业务逻辑                              │
│  - 事务控制                                      │
│  - 缓存管理                                      │
└──────────────────┬──────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────┐
│        数据访问层（DAO / Repository）            │
│  - 与数据库交互                                  │
│  - 数据转换                                      │
└──────────────────┬──────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────┐
│              数据库层                            │
```

### 3.2.2 技术选型

**后端技术栈：**
- 开发语言：Java 17
- 核心框架：Spring Boot 2.7.18
- 安全框架：Spring Security
- ORM框架：MyBatis-Plus 3.5.3.1
- 数据库：MySQL 8.0+
- 缓存：Redis 6.0+

**前端技术栈：**
- HTML5
- Bootstrap 5.3
- JavaScript
- Thymeleaf模板引擎

### 3.2.3 模块划分

系统分为以下核心模块：

1. **用户管理模块**：负责用户注册、登录、权限管理
2. **宠物管理模块**：负责宠物信息的增删改查
3. **领养申请模块**：负责领养申请的提交、审核
4. **预约管理模块**：负责探视预约的管理
5. **文件上传模块**：负责图片和文件的上传管理
